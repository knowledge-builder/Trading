===========================================================
Problem Definition
===========================================================

The incoming WebSocket messages are encoded using

    Protocol Buffers (protobuf)

instead of plain JSON.

Python currently displays the raw binary payload because no decoder
has been provided.

As a result, the application cannot yet access fields such as:

• Symbol
• Timestamp
• Open
• High
• Low
• Close
• Volume
• Interval

Although the market data is arriving successfully, it remains
unusable until it is decoded.

===========================================================
Why This Happens
===========================================================

The subscribed channel is

    spot@public.kline.v3.api.pb@BTCUSDT@Min1

Notice the

    .pb

suffix.

This indicates that the exchange uses

    Protocol Buffers

for serialization.

Protocol Buffers are a compact binary format developed by Google.

Advantages include:

• Smaller packets
• Faster transmission
• Lower latency
• Faster parsing
• Lower bandwidth consumption

Most professional market data vendors use binary serialization
instead of JSON.

Examples include:

• Databento (DBN)
• CME MDP
• Coinbase
• Binance (selected feeds)
• MEXC

===========================================================
Missing Component
===========================================================

To decode protobuf data, a message schema is required.

Normally exchanges publish

    .proto

files.

These define every message structure.

Example:

    message Kline {

        ...

    }

Without the schema,

the binary bytes cannot be interpreted into meaningful values.
